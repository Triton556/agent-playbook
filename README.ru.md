# Agent Playbook — workflow для агентов

Этот пакет переносит workflow версии 1.2.0 и 24 локальных навыка с полными текстами, справками, данными и помощниками. Можно подключить всё целиком, профиль или отдельный навык с его зависимостями. Модели и инструменты предоставляет выбранный клиент.

Главное требование: упаковка сохраняет метод, критерии и проверки. Тексты не заменяются краткими пересказами; изменение машинных путей и привязок явно фиксируется в manifest.json. Разные модели всё же могут давать разные результаты — равенство будущих работ не объявляется доказанным.

## Установка

**Сначала посмотрите [визуальный гид по профилям](docs/PROFILES.ru.md):** назначение харнесса, выбор по задаче и результаты между этапами — от шести видов робота до вращающейся модели.

Нужен Python 3.12+ (в том числе для проверки Windows junction). Для помощников состояния, памяти и сессий Codex нужен Node.js 22+. На Windows вместо `python` можно указать полный путь к своему интерпретатору.

```text
git clone https://github.com/Triton556/agent-playbook.git
cd agent-playbook
python harness.py plan --client codex --target ../мой-проект --profile full
python harness.py install --client codex --target ../мой-проект --profile full
python harness.py verify --client codex --target ../мой-проект
python harness.py doctor --client codex --target ../мой-проект
```

На Windows клонируй с `git clone -c core.longpaths=true https://github.com/Triton556/agent-playbook.git`: эта настройка включает длинные пути для вложенных ресурсов данного клона.

Открой новый чат клиента в целевом проекте. Проверь обнаружение навыков и реальный рабочий сценарий. Успешная копия файлов не заменяет эту проверку.

Клиенты: `codex`, `claude`, `deepseek`, `generic`. Установщик записывает в проект, а не в глобальную конфигурацию клиента. Для полного режима он встраивает весь основной набор инструкций в управляемый блок AGENTS.md или CLAUDE.md, сохраняя существующий текст.

## Что подключать

| Цель | Выбор |
|---|---|
| Весь процесс | `--profile full` |
| Разработка | `--profile engineering` |
| UI, объяснения, визуальные миры | `--profile visual` |
| Воксельные ассеты | `--profile voxel` |
| Память | `--profile memory` |
| Работа над инструкциями | `--profile instructions` |
| Отдельный навык | `--skills dev-domain-model` или другое имя из `catalog` |

`creative-direction` помогает выбрать замысел до реализации: UI, игра, текст, видео, движение или 3D. Он входит в `full`, `engineering`, `visual` и `voxel`; при уже принятом направлении повторный поиск вариантов не требуется.

`agent-sessions-codex` предназначен для оркестратора — Claude, другого Codex или любого агента с нужными локальными инструментами. Он помогает написать бриф, запустить или продолжить видимый в приложении Codex тред и проверить результат. Входит в `full`, `engineering` и `instructions`; отдельно устанавливается через `--skills agent-sessions-codex`, в том числе с `--client claude`. Оркестратор предлагает каждую сессию вместе с режимом доступа и запускает её только после согласия пользователя. Нужны Node.js и доступного Codex CLI с настройками и историей самого пользователя. Подробнее — [интеграция сессий](docs/INTEGRATIONS.md#agent-sessions-codex-for-orchestrators).

`agent-sessions` обобщает это на любых исполнителей через адаптеры с единым [контрактом](payload/skills/agent-sessions/references/contract.md). В комплекте проверенный вживую адаптер `codex`, непроверенный `claude-code` и справка, как написать адаптер для другого клиента, например OpenCode или DeepSeek harness. Каждый адаптер сообщает, что на самом деле обеспечивают его режимы доступа, и отказывается от режима, который не может обеспечить. Входит в `engineering`, `instructions` и `full`, отдельно — `--skills agent-sessions`.

`--workflow` включает полный маршрут и все 24 модуля: иначе его ветки могли бы указывать на отсутствующие навыки. Перед записью `plan` показывает полный состав с зависимостями, включая вызовы навыка по имени. Отдельный навык получает небольшой блок с правилами доступа новой установки; весь общий маршрут при этом не активируется.

Подробнее: [руководство для установки агентом](INSTALL_FOR_AGENTS.md), [маршрут и загрузка контекста](docs/WORKFLOW_GUIDE.md), [интеграции, хуки и лимиты инструкций](docs/INTEGRATIONS.md). Установщик проверяет бюджет проектных инструкций Codex и конфликт AGENTS.override.md; он не обрезает текст и не меняет глобальный config.toml. MCP, доверие хукам и обслуживание собственной памяти настраиваются и проверяются отдельно по этому руководству.

## Порядок работы

Исходный запрос и уточнения → выбор участия пользователя и отдельно проверяющего → основания при конкретном неизвестном → связное предварительное представление → реализация → собственные проверки и выбранные точки приёмки → исправление подтверждённых проблем → завершение и память. Отдельный ревьюер запускается только по явному согласию для этой задачи, в согласованном объёме и числе раундов; исправление само по себе не создаёт новый раунд. [Роли инструкций и единый пилот](docs/INSTRUCTION_MAINTENANCE.md).

Автор сам выполняет тесты и организует ревью. Ревьюер получает запрос, уточнения, конкретные ожидания, условия использования, текущую версию и доступный способ проверки. Самооценки автора раскрываются после первого собственного осмотра. Автоматический pass, агентский осмотр и приёмка человека остаются разными статусами.

## Что нужно настроить у себя

Свежий ревьюер требует фактического разрешения владельца и инструмента нового контекста. Браузер, изображения, генерация изображений и документы требуют доступных инструментов клиента. Память использует свою разрешённую базу. Управление личной VM исключено из публичного пакета. Личные данные автора пакета не импортируются.

Для памяти можно создать пустую базу через `python harness.py init-memory --target ../мой-проект --client codex`. Синхронизация и расписание при этом не включаются. Подробности — в [установке для агентов](INSTALL_FOR_AGENTS.md) и [совместимости](docs/COMPATIBILITY.md).

Все проведённые проверки и ограничения указаны в [VALIDATION](docs/VALIDATION.md). Диспетчер и отменённые пять дополнений не возвращаются.

Инструкции для агентов переведены на английский. Общение с пользователем и содержимое базы знаний по умолчанию остаются на русском; явный запрос пользователя может изменить язык конкретного результата. Правило действует и при полной установке, и при выборе отдельных навыков.

## Обновление 0.x → 1.0.0

Обнови этот же клон, сохранив его приватную папку `.harness-state/receipts/`. Повтори прежние команды `plan` и `install` с тем же проектом, клиентом, профилем/навыками, флагом workflow и сохранёнными в пакете привязками, затем выполни `verify`. Исключённые флаги лаборатории больше не передавай: прежние значения при миграции игнорируются. План показывает `migration_from` и число `obsolete_owned_files`, ничего не записывая. Старые имена в `--skills` принимаются с предупреждением в stderr; в плане и установке используются новые. Полная [таблица переименований](CHANGELOG.md#100) — в истории выпуска. Прямой запрос удалённого навыка даёт понятную ошибку.

Установщик сверяет квитанцию с исходной приватной записью, проверяет старые файлы и управляемый блок, обновляет неизменённые управляемые файлы и удаляет только устаревшие файлы, которыми владеет. Чужие соседние файлы, ранее существовавшие идентичные файлы и текст вне блока сохраняются, включая BOM/CRLF. Изменённый или пропавший старый файл, правка блока, другие параметры, отсутствие приватной записи или конфликт нового пути останавливают обновление до записи. Устрани указанный конфликт с сохранением пользовательского содержимого и повтори команду. Для другого клона нужен разрешённый перенос исходной приватной записи; одной квитанции проекта недостаточно. Пустые старые папки могут остаться. Перед обновлением сохрани резервную копию проекта и квитанций; клон 0.x пригодится для восстановления. Глобальные настройки клиентов не меняются.
