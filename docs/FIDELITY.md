# Fidelity and non-degradation contract

This export preserves the active configured workflow, not retired experiments or another owner's private environment.

## Preserved

- Full global base, WORKFLOW, author self-testing/independent review procedure.
- 24 custom skill entrypoints, their complete references, source/provenance licenses, searchable UI datasets and original helpers.
- Research triggers, cheap coherent representation, style/function/context/readability/use criteria.
- Six-view voxel preflight and kit/world proportions before detailed construction; later actual voxel inspection.
- Technical, semantic, actual visual and human verdicts as separate claims.
- Completeness, state/evidence revision checks, conservative invalidation, cause verification and scoped regression.
- Memory capture/checkpoint/idempotence, curation/cloud-exchange/sync procedures with privacy and real receipt checks.
- Selective context loading and the owner's actual action permissions.

The method is not condensed into the README. Installed instructions and supporting resources carry the actual behavior. A selected module includes its linked sibling closure. Full mode preserves the always-loaded base layer inline; BASE-RULES.md avoids accidental duplicate nested startup rules.

## Explicit portable changes

`manifest.json` records source/export SHA for each file and a list of transformations. Most files are byte-identical. Changes are scoped to:

1. Machine paths become installation bindings: harness root, interpreter and memory/evidence locations.
2. The original owner's label becomes a generic user/curator label. User-specific data, remote settings and schedule receipts are not inherited by a new installation.
3. `agent-worklog.mjs` resolves the same Python validator relative to its installed sibling and uses an interpreter environment binding.
4. `kb-writer.mjs` imports the same memory library relatively and fixes the authorized vault at process startup via HARNESS_KB_ROOT.
5. Three vendor links resolve to the retained `INSTRUCTIONS.md` entry instead of an absent nested `SKILL.md`. The entry body is unchanged; no duplicate native skill is introduced.
6. The actual hook event wiring is preserved as a rendered opt-in template. Original trust hashes are never transferred; real native review/registration remains required.

Owner substitutions use word boundaries and leave upstream author names, searchable datasets, font-license attribution and component license notices intact. Skills-only mode receives a small deployment/permission startup block; it does not imply activation of all global routes.

These changes do not weaken tests, criteria, command schemas, operation limits or permission checks. Actual user consent is still required. Original source files and configuration stay outside the export target and are checked separately during build.

## What tests can establish

| Evidence | Valid claim |
|---|---|
| Source/export/installed hashes and documented bindings | File/composition fidelity |
| Real install/reinstall/conflict/removal scenarios | Installer behavior and preservation |
| Same helper inputs and output hashes/invariants | Helper reproduction for those cases |
| Actual native catalog response | Discovery in that client/version/environment |
| Matched end-to-end tasks and independent observations | Observed process/result comparison at that scope |
| Actual user's response | Human acceptance at that scope |

Hash tests do not establish that a model reads every condition or creates good graphics. A model can still make mistakes with identical instructions. This repository must not claim quality parity, cost reduction or identical creative output without the relevant observed evidence.
