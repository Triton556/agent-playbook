# Delegation-specific requirements

Open only when preparing a worker assignment with a missing output, dependency, model/route, access choice or acceptance scenario. Reuse the existing task decisions; do not replay a general task interview.

## Delegation-specific additions

| Missing item | Action | Result |
| --- | --- | --- |
| Output or dependency | Identify the deliverable and which other output it consumes. | Brief and scheduling edge. |
| Model, effort or route | Read the saved profile/task choice; ask if it does not cover this assignment. | Explicit selected settings, not a fresh setup for an existing worker. |
| Access or new cost | Describe the particular required operation and current authorization gap. | Decision before that operation; independent covered work continues. |
| Acceptance | Name the user steps or public contract and observable expected outcome. | A worker result can be checked independently of its implementation. |

The current task/project launch scope is defined in [session guide, step 5](../../agent-sessions/references/session-guide.md#5-check-the-authorized-scope-and-launch). Existing authorization is reused; a profile alone is not permission.
