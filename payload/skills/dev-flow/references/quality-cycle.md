# Quality adapter for a series or repeated defect

Use for several authored outputs, a procedural family, or a repeated semantic defect. [WORKFLOW](../../../workflow/WORKFLOW.md) owns task progression; [task-brief-and-acceptance](task-brief-and-acceptance.md) owns the single brief and acceptance program; [human-perspective-review](human-perspective-review.md) owns direct observation. This adapter adds only series-specific checks.

## Before expanding a series

Declare the required outputs in the existing plan. Test one whole representative and meaningful extremes: largest mass, finest feature, crowded contact or an intentional exception. Identify the accepted range, shared dependencies, seed/parameters and output revisions. Reuse approved family ranges; a new action, identity or out-of-range parameter reopens only the affected design question.

Name objective, style, function and context in the same brief, including what must survive a change. Keep accepted examples as protected baselines. Shared helpers need class parameters and distinguishing checks: reuse must preserve the meaning/identity of each member, not merely produce valid files.

## Inspect and record

Check series members using specialist views/interactions and format checks. Evidence grades: see [human-perspective-review, Readiness and transfer](human-perspective-review.md#readiness-and-transfer). Reuse: see [task-brief-and-acceptance, 7. Execution, verification and completion](task-brief-and-acceptance.md#7-execution-verification-and-completion).

For repeated failure, add a distinguishing member/extreme check and protect deliberate style exceptions. Failure records: see [quality-ledger, Schema version 1](quality-ledger.md#schema-version-1). Transition: see [WORKFLOW, Work route](../../../workflow/WORKFLOW.md#work-route).

Use [quality-ledger](quality-ledger.md) when series/dependency evidence benefits from machine validation or the project requires it. Output records: see [task-state, Long-task state and completeness](task-state.md#long-task-state-and-completeness).

## Repair and transfer

Repairs follow WORKFLOW, Check, repair and finish. Add checks of the affected member, relevant family extremes and protected examples. Invalidation: see quality-ledger, Schema version 1.

Reusable lessons keep trigger, observation, mechanism/hypothesis, check, scope/exceptions and example links. General task rules stay in WORKFLOW, subject-specific rules in the profile, and project values in the project. This adapter adds no new interview, reviewer or model experiment.
