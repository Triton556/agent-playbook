name: kb-save
description: Сохранить новые полезные сведения текущего разговора пользователь в файловый INBOX, указав источник, основания и статус.
---

База на ПК: `{{MEMORY_ROOT}}`. В Cloud используй проверенную копию репозитория назначенный куратор.

Прочитай SYSTEM/workflows/capture.md только при первом использовании или изменении процедуры. Короткие записи сохраняй сам; для объёмного итога можно использовать одного агента памяти по постоянному разрешению пользователь в AGENTS.md. Правила передачи и проверки результата находятся в том же workflow; делегирование не является обязательным этапом. Составь короткий JSON новых сведений по схеме workflow. На ПК предпочитай доступные инструменты `danil_kb_writer`: `kb_capture({payload})` или `kb_checkpoint({session_id,turn_id})`. Их ограниченный постоянный доступ пользователь согласовал 12.10.2026. Если инструмент отсутствует в каталоге текущего чата, используй существующий CLI через stdin: `node SYSTEM/scripts/kb.mjs capture` из папки базы; соблюдай действующие права файлового доступа. В PowerShell используй объект → ConvertTo-Json → stdin, а не интерполяцию текста пользователя в команду. Из другой папки укажи абсолютный путь к скрипту.

Используй реальные идентификаторы из хука; новый этап получает новый batch_key, повторная попытка — прежний. При запрете пользователя сохранять содержимое или отсутствии новых знаний выполни checkpoint без записи содержимого. Подтверждай сохранение по успешному результату и существующему файлу. На ПК данные остаются локально до Git-sync Планировщика Windows: раз в час и при входе пользователя. назначенный куратор синхронизирует свою облачную копию и выполняет ежедневный разбор.
