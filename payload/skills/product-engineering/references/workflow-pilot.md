# Проверочная задача и метрики

Открывай при явной проверке нового workflow, сравнении способов или сборе метрик. Обычная работа не превращается в автоматический модельный benchmark. пользователь задаёт следующую тестовую задачу; описание кейсов не разрешает запуск дополнительных моделей/агентов или новые расходы.

## Перед прогоном

Запиши исходный brief, модель/настройки при доступности, согласованный бюджет/доступ, загруженные ветки и ожидаемые результаты. Определи критерии до создания. Для сравнения используй одинаковый вход, ограничения и свежие контексты; номер попытки и предыдущее знакомство с результатом известны. Сохранённые Gen2 примеры — обучающие для процесса, не независимый новый тест творчества.

Предложенный smoke — три случая × два условия: UI с неоднозначным действием/данными и восстановлением; новый 3D-объект с неоднозначным считыванием/геометрией; динамика/сцена с характером. Включи намеренно допустимый необычный элемент для ложных тревог. Это стартовый набор при соответствующем поручении, а не обязательные шесть запусков после каждой правки навыка.

## Что считать

| Показатель | Источник и знаменатель |
| --- | --- |
| Выполнение | Проверенные обязательные выходы / объявленные выходы; пропавший объект виден |
| Повторные вопросы | Повторы после согласия / вопросы о решениях: repeated + clarification + new_scope; technical отдельно |
| Вмешательства | Новое требование, пользовательский отзыв, разрыв связи, намеренная остановка и необоснованный стоп различаются |
| Качество | Технические, смысловые, визуальные критерии, реальные дефекты и ложные тревоги раздельно |
| Восприятие | Узнавание/ожидание и сохранение характера; агентская гипотеза отдельно от ответа пользователь |
| UI | Успех действия, ошибки/помощь, восстановление, сохранность работы; время/возвраты/клики при доступном измерении |
| Исполнение метода | Выбрана нужная ветка, основания действительно просмотрены, прототип/проверка применены по триггеру |
| Стоимость | Фактические время/токены при наличии телеметрии; неизвестное не ноль |

Показывай исходные числа, знаменатель, период, способ сбора и ограничения. Нулевой знаменатель означает «не определено». Журнал агента — его разметка, не независимое доказательство; пропущенные события не превращаются в отсутствие проблемы. Приятный тон и точность причины — разные показатели.

## Запись и вывод

Для событий используй существующий agent-worklog; команда `metrics` экспортирует агрегат явно записанных событий без содержания разговора. Для результатов — критерии и актуальные свидетельства/ledger. Каждому выполненному кейсу нужен артефакт; неисполненный остаётся неисполненным. Детерминированные тесты инструмента и фактическая задача агента имеют разные статусы.

Один smoke выявляет грубый сбой и исполнимость, но не статистическую устойчивость или вклад каждой оптимизации. Если одновременно изменилось несколько компонентов, наблюдается их совокупный эффект. Сохрани полезный кейс и контрпример через kb-save, затем корректируй минимально затронутую ветку.
