# Review a working interface

This stage owns actual rendering and actions. Use the current [acceptance program](../product-engineering/references/task-brief-and-acceptance.md); [visual-quality](references/visual-quality.md) defines one pass over the affected surface. Open-ended inspection supplements the criteria.

When a mockup exists, compare the same route, state, data, size/zoom. Under [UI preflight, stage 4](../product-ui-design/references/design-preflight.md#4-compare-the-working-ui-with-the-basis), distinguish quality of the basis, fidelity of transfer and scenario behavior. Without a mockup, check available requirements/current system and note the gap; a retrospective description does not establish preflight.

For behavior, use the relevant [interaction-quality](../product-ui-design/references/interaction-quality.md) branch. One actual scenario and its current evidence may cover UI, behavioral and semantic criteria; do not rerun it just because another check has a different name. Assess perception/preservation through the [shared protocol](../product-engineering/references/human-perspective-review.md), without another general inspection.

In review-only mode, deliver observable findings and locations. Authorized fixes follow WORKFLOW; a new visual language returns to [design](../product-ui-design/SKILL.md), and an unexplained functional cause goes to [debugging](../product-debugging/SKILL.md).

Impeccable is a specialist reference/detector, not a second mandatory audit. Scripts contains the local context wrapper without upstream interviews or subagents. Actual inspection outranks an abstract count; evaluate stylistic warnings against the brand.
