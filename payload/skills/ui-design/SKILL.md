# UI/UX design

This stage owns the user flow and visual decisions; shared requirements and participation checkpoints come from [WORKFLOW](../../workflow/WORKFLOW.md) and the saved brief. Establish the deliverable: UX plan, concept or implementation. When a new surface or redesign direction is open, run [creative-direction](../creative-direction/SKILL.md) first; a small refinement goes straight to the fix. [Interface-design](references/interface-design.md) distinguishes a new surface, refinement and redesign.

Before composition, establish the action, expected result and recovery. A new flow, substantial redesign or screen series uses [UI preflight](references/design-preflight.md): related states, a sufficient mockup/prototype and saved basis. A small edit uses the accepted basis and affected states. [Interaction-quality](references/interaction-quality.md) provides targeted criteria for actions, forms, tables, filters or complex desktop UI.

Use one design system, starting with project components/tokens. For a new dashboard/substantial redesign, run a targeted [UI/UX Pro Max](../ui-reference/SKILL.md) search, inspect useful real examples and connect the selected technique to the task. For a specific UX/accessibility/stack question, its relevant reference suffices. [Taste v1](../ui-taste-reference/SKILL.md) supplies an individual art-direction technique when needed, without a second design system or mandatory animation.

Landing/promotional pages use [landing-design](references/landing-design.md). Working screens follow their product task. User conditions, existing brand, accessibility and stack outrank recipes.

After implementation, pass the basis and current UI to [ui-review](../ui-review/SKILL.md). Design-only ends with decisions/mockup and properties verifiable only in implementation; behavior integration belongs to [dev-implement](../dev-implement/SKILL.md) when requested. Sources and local adaptation: [sources.json](sources.json).
