# Маршрут работы

Это маршрут текущего агента, а не список всех обязательных навыков. Разрешения задают AGENTS и последние указания пользователь. Ясная локальная задача начинает с затронутого этапа.

1. **Восстановить задачу.** Запрос, существенные поправки, текущий результат, разрешённый объём и ближайший проверяемый шаг. Для новой существенной/размытой задачи используй [задание и приёмку]({{HARNESS_ROOT}}/skills/product-engineering/references/task-brief-and-acceptance.md): тематические вопросы, сохранённая основа, участие пользователь и отдельный выбор ревью. Известные ответы переиспользуй.
2. **Выбрать один основной этап.** Открой его навык; дополнительные справки — при конкретном триггере. Неизменённое руководство в том же контексте повторно не загружай. При переходе/восстановлении читай актуальную основу и состояние задачи, затем только нужные изменённые или утраченные инструкции.
3. **Разрешить риск до дорогого шага.** Если критичное свойство не имеет основания, источники противоречат или дефект повторяется без причины — [reference-grounding]({{HARNESS_ROOT}}/skills/product-engineering/references/reference-grounding.md). Для дорогого нового направления проверь минимальное целое представление, различающее спорное свойство. Выбранные человеческие точки приёмки обязательны перед зависимым продолжением.
4. **Сделать полезный результат.** Выполняй согласованный объём завершёнными частями. В одном существующем плане держи требования/решения, текущую версию, проверки, существенное открытое и следующий шаг. Машинный graph/ledger нужен при реальной серии, сложных зависимостях или требовании проекта; он ссылается на план, не дублирует его.
5. **Проверить результат.** Сверь актуальные требования и программу приёмки по [общей справке](../skills/product-engineering/references/task-brief-and-acceptance.md). Соразмерные технические проверки и фактическое использование/осмотр нужной модальностью. Для стиля, узнавания и понятности — [протокол восприятия]({{HARNESS_ROOT}}/skills/product-engineering/references/human-perspective-review.md): первое считывание, прямое сравнение с основанием, правильный состав изменения и сохраняемое. Неизвестное остаётся непроверенным. Авторская, независимая и человеческая оценки различаются; [отдельное ревью]({{HARNESS_ROOT}}/workflow/independent-review.md) выполняется только если выбрано.
6. **Исправить и завершить.** Подтверди причину, исправь, повтори исходный провал и затронутую регрессию. Круг имеет новый сигнал, подтверждённый дефект или проверяемую гипотезу; одинаковый осмотр не создаёт нового основания. Сохрани провал/поправку и текущий статус без переписывания истории. Сдавай результат с проверками и ограничениями; новый полезный урок сохрани через kb-save с областью применимости.

| Результат | Основной вход |
| --- | --- |
| Полная разработка | product-engineering как координатор; узкий запрос сразу product-planning / implementation / debugging / testing |
| Интерфейс | product-ui-design до нового решения, product-ui-review для фактического осмотра. Один сценарий, одна система; дополнительные UX/taste-источники адресно |
| Воксели | voxel-model-craft: масштаб, части, источники, достаточный preflight, текущая модель и нужные виды |
| Интерактивная визуализация / мир | visual-experiment-craft; UI и воксели только для соответствующей части результата |
| Текст / исследование | задача/аудитория → основания и неопределённость → содержательная самопроверка. Инженерные схемы состояния и визуальные тесты только если такой артефакт действительно создаётся |
| Файл / облачный документ | Один навык целевого формата/редактора; его реальные проверки экспорта/отображения. Наличие слова «презентация» не превращает страницу сайта в PPTX |
| Бытовой ответ | Прямой практический результат и нужная проверка, без проектного процесса |
| Безопасность / лаборатория | Проектная рамка и нужный профильный навык; границы AGENTS сохраняются |

Для нового дашборда или существенного UI-редизайна до вёрстки выполни адресный поиск ui-ux-pro-max и просмотри подходящие реальные примеры. Свяжи выбранные приёмы с главным вопросом и действием пользователя; используй одну дизайн-систему. Целевое устройство и реальная ширина окна пользователь определяют проверку. Дашборд показывает связи/сравнения/выводы, согласованно обновляет графику и подписи; предположения и числовые основания обозначены. Mobile добавляется по задаче, а не из-за слова «лендинг».

Профильные документы хранят специфические критерии. Общий порядок требований/состояния/прав не пересказывается в каждой ветке. Исторические исследования и образцы загружай по конкретному вопросу, не как обязательную библиотеку.


Для серии результатов или повторного смыслового дефекта [quality-cycle](../skills/product-engineering/references/quality-cycle.md) добавляет отбор представителей и защиту принятых примеров. Для сравнительного эксперимента действует один [workflow-pilot](../skills/product-engineering/references/workflow-pilot.md); обычная правка инструкций не запускает его.

Владельцы общих процедур: вопросы/основа/критерии — task-brief-and-acceptance; наблюдение и сохраняемое — human-perspective-review; машинное состояние — task-state; записи свидетельств — quality-ledger; согласованный второй взгляд — independent-review. Указатель из профиля не требует повторять процедуру или перечитывать неизменённое руководство. Один актуальный проход может подтверждать несколько критериев, если его условия и наблюдения достаточны для каждого.
