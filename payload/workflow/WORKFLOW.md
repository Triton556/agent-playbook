# Work route

This is the current agent's route, not a list of mandatory skills. AGENTS and the user's latest instructions determine permissions. A clear local task starts at its affected stage.

1. **Recover the task.** Establish the request, material corrections, current result, authorized scope and next verifiable step. For a new substantial/ambiguous task, use the [task brief and acceptance]({{HARNESS_ROOT}}/skills/product-engineering/references/task-brief-and-acceptance.md): themed questions, a saved basis, the user's participation and a separate review choice. Reuse known answers.
2. **Choose one primary stage.** Open its skill; read additional references on a specific trigger. Do not reload an unchanged guide still in context. On transition/recovery, read the current basis and task state, then only changed or lost instructions that are needed.
3. **Resolve risk before an expensive step.** If a critical property lacks support, sources conflict or a defect recurs without an explanation, use [reference-grounding]({{HARNESS_ROOT}}/skills/product-engineering/references/reference-grounding.md). For an expensive new direction, check the smallest coherent representation that distinguishes the disputed property. Selected human checkpoints are mandatory before dependent work continues.
4. **Produce a useful result.** Complete the agreed scope in finished pieces. Keep requirements/decisions, current version, checks, material open issues and next step in one existing plan. A machine graph/ledger is needed for a real series, complex dependencies or a project requirement; it references the plan instead of duplicating it.
5. **Verify the result.** Check current requirements and the acceptance program using the [shared reference](../skills/product-engineering/references/task-brief-and-acceptance.md). Perform proportional technical checks and actual use/inspection in the required modality. For style, recognition and clarity, use the [human-perspective protocol]({{HARNESS_ROOT}}/skills/product-engineering/references/human-perspective-review.md): first reading, direct comparison with the basis, correct change membership and preservation. Unknowns remain unverified. Distinguish author, independent and human assessments; perform [separate review]({{HARNESS_ROOT}}/workflow/independent-review.md) only when selected.
6. **Repair and finish.** Confirm the cause, fix it, repeat the original failing case and affected regression. A round needs a new signal, confirmed defect or testable hypothesis; the same inspection does not create new evidence. Preserve the failure/correction and current status without rewriting history. Deliver results with checks and limitations; save a useful new lesson through kb-save with its applicability limits.

| Everyday answer | Direct practical result and necessary verification, without a project process |
| Security / lab | Project frame and relevant specialist skill; AGENTS boundaries remain in force |

Before implementing a new dashboard or substantial UI redesign, run a targeted ui-ux-pro-max search and inspect relevant real examples. Connect selected techniques to the user's main question and action; use one design system. the user's target device and actual window width determine verification. A dashboard shows relationships/comparisons/conclusions, updates graphics and labels consistently, and identifies assumptions and numerical grounds. Add mobile coverage when the task requires it, not because it says “landing page.”

Specialist documents hold subject-specific criteria. Do not retell shared requirements/state/permission procedures in every branch. Load historical research and examples for a specific question, not as a mandatory library.

For a series or recurring semantic defect, [quality-cycle](../skills/product-engineering/references/quality-cycle.md) adds representative selection and protection of accepted examples. Comparative experiments use one [workflow-pilot](../skills/product-engineering/references/workflow-pilot.md); ordinary instruction edits do not trigger it.

Shared procedure owners: questions/basis/criteria — task-brief-and-acceptance; observation and preservation — human-perspective-review; machine state — task-state; evidence records — quality-ledger; an agreed second view — independent-review. A specialist pointer does not require repeating a procedure or rereading an unchanged guide. One current pass may support several criteria when its conditions and observations suffice for each.
